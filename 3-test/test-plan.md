# Тест-план: Приложение «Глини» (бэкенд + мобильный клиент)

## 1. Введение

Тестирование монолитного Go-бэкенда (REST API) и Flutter-клиента для записи на мастер-классы гончарной мастерской.

## 2. Объект тестирования

| Компонент | Технологии | Доступ |
|---|---|---|
| Go REST API | chi + sqlx + SQLite + goose + JWT | `http://localhost:8080` (dev) |
| Flutter mobile client | flutter_riverpod + go_router + dio | Android-APK |

## 3. Объём тестирования (Scope)

### Тестируется

1. **Аутентификация (ФТ-01, ФТ-02, UC-01, UC-02)**
   - Регистрация нового клиента
   - Вход по логину/паролю
   - Валидация входных данных
   - JWT-токен (24h, claims)

2. **Каталоги read-only (ФТ-03, ФТ-09, ФТ-10, UC-03)**
   - GET /slots — список с фильтрами (dateFrom, dateTo, masterId, programId)
   - GET /slots/:id — детали слота
   - GET /masters — список мастеров
   - GET /masters/:id — профиль мастера
   - GET /programs — список программ
   - GET /programs/:id — детали программы

3. **Бронирование (ФТ-04, ФТ-05, ФТ-06, UC-04, UC-05, UC-06)**
   - Создание брони (POST /bookings)
   - Просмотр своих броней (GET /bookings, GET /bookings/:id)
   - Отмена брони (PATCH /bookings/:id/cancel)
   - Бизнес-правила: ≥4ч → отмена, <4ч → 422
   - Двойная бронь → 409
   - Нет мест → 409
   - Чужая броня → 404

4. **Оценка мастера (ФТ-07, UC-07)**
   - Создание оценки (POST /ratings)
   - Временное окно: 1–48ч после окончания слота
   - Повторная оценка → 409

5. **Безопасность (НФТ-02, НФТ-07)**
   - Доступ к защищённым эндпоинтам без токена → 401
   - Клиент видит только свои брони
   - Клиент записывает только себя

6. **Мобильные экраны (SCR-001–SCR-009)**
   - Вход / Регистрация
   - Расписание (список слотов, фильтрация по дате)
   - Детали слота
   - Мои записи
   - Детали брони
   - Оценка мастера
   - Профиль мастера
   - Программа

### НЕ тестируется

- Push-уведомления (ФТ-08, НФТ-06) — не реализованы
- Админ-панель / управление мастерами/слотами/программами (не входит в поставку)
- Производительность / нагрузочное тестирование
- iOS-сборка (только Android)
- Офлайн-сценарии (кеширование не реализовано)

## 4. Риски

| Риск | Мера |
|---|---|
| SQLite — нет конкурентных транзакций (sequential writes) | Проверить атомарность бронирования в однопоточном сценарии |
| Нет идемпотентности (Idempotency-Key) | Двойной POST /bookings от одного клиента = 409 (unique index) |
| Seed-данные генерируются при старте, слоты в будущем | Тесты могут быть нестабильны по времени (cancel <4h) |
| Мобильный клиент без обработки всех HTTP-статусов | Проверить UI при 401, 409, 422, 500 |

## 5. Стратегия тестирования

- **Функциональное:** ручное (postman/curl) для API + ручное на устройстве для мобильного клиента
- **Негативное:** каждый эндпоинт с невалидными данными
- **Краевые случаи:** ровно 4ч до начала (cancel), ровно 1ч после (rating), ровно 48ч (rating)
- **Безопасность:** 401 без токена, чужая бронь → 404

## 6. Окружение

| Параметр | Значение |
|---|---|
| Backend | Go 1.22, SQLite, `http://localhost:8080` |
| Адрес для мобильного | `192.168.1.101:8080` |
| Device | Android, ADB `192.168.1.219:39937` |
| AUTH_SECRET | `dev-secret` |
| Seed data | 3 мастера, 3 программы, слоты на 7 дней |

## 7. Критерии качества

- P0 (критические): все бизнес-правила (двойная бронь, отмена ≥4ч, чужая броня)
- P1 (важные): корректная работа CRUD, фильтрация, авторизация
- P2 (желательно): UI/UX, форматирование данных, краевые случаи
