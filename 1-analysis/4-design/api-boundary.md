# Границы API и потоки данных

## Принцип

Существующий бэкенд — **black-box**. Приложение взаимодействует с ним через API-контракт. Бэкенд — источник истины: гарантирует атомарность бронирования, хранит данные, управляет расписанием. Клиентское приложение — **тонкий клиент**, который:

1. **Потребляет** данные (слоты, мастера, программы) — GET-запросы
2. **Отправляет** команды (регистрация, бронь, отмена, оценка) — POST/PATCH-запросы
3. **Получает** push-уведомления (подтверждение записи, напоминание за 2 часа, отмена мастерской)

## Матрица API-операций

| Операция | Метод | Сущность | Режим | ФТ | Примечание |
|---|---|---|---|---|---|
| Регистрация | `POST /auth/register` | Клиент | **Write** | ФТ-01 | Создаёт учётную запись |
| Вход | `POST /auth/login` | Клиент | **Read** | ФТ-02 | Возвращает токен сессии |
| Расписание слотов | `GET /slots?dateFrom=&dateTo=` | Слот | **Read** | ФТ-03 | Список доступных слотов |
| Детали слота | `GET /slots/:id` | Слот | **Read** | ФТ-03 | Полная информация о слоте |
| Создать бронь | `POST /bookings` | Бронь | **Write** | ФТ-04 | Указывает слот + прокат |
| Мои брони | `GET /bookings?clientId=` | Бронь | **Read** | ФТ-05 | Список броней клиента |
| Детали брони | `GET /bookings/:id` | Бронь | **Read** | ФТ-06 | Полная информация |
| Отменить бронь | `PATCH /bookings/:id/cancel` | Бронь | **Update** | ФТ-06 | Меняет статус |
| Создать оценку | `POST /ratings` | Оценка | **Write** | ФТ-07 | Оценка мастера |
| Профиль мастера | `GET /masters/:id` | Мастер | **Read** | ФТ-09 | Имя, фото, рейтинг, уровень |
| Список мастеров | `GET /masters` | Мастер | **Read** | ФТ-09 | Для выбора/отображения |
| Программа | `GET /programs/:id` | Программа | **Read** | ФТ-10 | Описание + вместимость |
| Список программ | `GET /programs` | Программа | **Read** | ФТ-10 | Для каталога |

## Где какие данные хранятся

| Данные | Где хранятся | Кто владелец | Кто читает |
|---|---|---|---|
| Клиенты | Бэкенд | Бэкенд | Приложение (только свой профиль) |
| Мастера | Бэкенд | Бэкенд (админка) | Приложение |
| Программы | Бэкенд | Бэкенд (админка) | Приложение |
| Слоты | Бэкенд | Бэкенд (админка) | Приложение |
| Брони | Бэкенд | Клиент + Бэкенд | Приложение (свои) |
| Оценки | Бэкенд | Клиент | Приложение (агрегированно) |
| Токен сессии | Приложение (storage) | Клиент | Приложение |

## Ключевые границы

- **Приложение НЕ создаёт и НЕ редактирует**: мастеров, программы, слоты расписания — это зона ответственности существующей инфраструктуры (админка)
- **Приложение СОЗДАЁТ**: клиента (регистрация), бронь (запись), оценку
- **Приложение ИЗМЕНЯЕТ**: статус брони (отмена)
- **Приложение УДАЛЯЕТ**: ничего — удаление не предусмотрено на стороне клиента
- **Бэкенд ГАРАНТИРУЕТ**: отсутствие двойных броней (атомарная проверка мест при `POST /bookings`)
- **Приложение ПОЛУЧАЕТ**: push-уведомления трёх типов — подтверждение записи, напоминание за 2 ч, отмена мастерской
- **Приложение ОБРАБАТЫВАЕТ**: отказ бэкенда при отсутствии мест (ошибка `409 Conflict`)
