# Модель домена

## ER-диаграмма

```
 ┌──────────────┐         ┌────────────────────┐
 │   Клиент     │1───────*│      Бронь         │
 │ (RW: C/R)    │         │ (RW: C/R/U, no D)  │
 └──────┬───────┘         └────────┬───────────┘
        │                          *│
        │1                          │1
        │                    ┌──────▼───────────┐
        │                    │  Слот расписания  │
        │                    │     (R only)      │
        │                    └──────┬───────────┘
        │                           │1
        │                    ┌──────▼───────────┐
        │                    │   Программа       │
        │                    │    (R only)       │
        │                    └──────────────────┘
        │
        │1
 ┌──────▼───────┐
 │   Оценка      │*
 │ (WO: C only)  │
 └──────┬───────┘
        *│
         │1
   ┌─────▼─────┐
   │  Мастер   │
   │ (R only)  │
   └───────────┘
```

**M:N связи:**
- Мастер \*────\* Программа (мастер ведёт несколько программ; программа ведётся несколькими мастерами)

---

## Описание сущностей

### 1. Клиент

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | ID (сервер) | Уникальный идентификатор |
| `login` | String | Email или телефон |
| `passwordHash` | String | Хеш пароля (на стороне бэкенда) |
| `createdAt` | DateTime | Дата регистрации |

**Режим доступа приложения: RW (Read-Write)**
- **C** — регистрация нового клиента (ФТ-01)
- **R** — чтение своего профиля (при входе, ФТ-02) и истории броней (ФТ-05)
- **U / D** — не в текущей поставке (смена пароля / удаление — отложено)

**Бизнес-правила:**
- Логин уникален в системе
- Пароль — минимальные требования длины/сложности (на стороне клиента и сервера)

---

### 2. Мастер

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | ID (сервер) | Уникальный идентификатор |
| `name` | String | ФИО мастера |
| `photo` | URL | Ссылка на фото |
| `rating` | Float (1.0–5.0) | Агрегированный рейтинг из оценок клиентов |
| `level` | Enum: `новичок`, `опытный` | Уровень мастера |
| `programs[]` | [Program.ID] | Список программ, которые ведёт |

**Режим доступа приложения: R (Read-only)**
- Только чтение данных, полученных от бэкенда (ФТ-09)
- Приложение не создаёт, не редактирует и не удаляет мастеров

---

### 3. Программа мастер-класса

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | ID (сервер) | Уникальный идентификатор |
| `name` | String | Название (например, «Лепка для новичков», «Гончарный круг») |
| `description` | String | Описание программы |
| `maxCapacity` | Integer | Новичковые ≤ 6, гончарный круг ≤ 10 |
| `masters[]` | [Master.ID] | Мастера, проводящие эту программу |

**Режим доступа приложения: R (Read-only)**
- Только чтение данных от бэкенда (ФТ-10)
- Никаких операций записи

---

### 4. Слот расписания

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | ID (сервер) | Уникальный идентификатор |
| `dateTime` | DateTime | Дата и время начала |
| `endTime` | DateTime | Окончание (~2–2.5 ч после начала) |
| `program` | Program | Ссылка на программу |
| `master` | Master | Ссылка на мастера |
| `totalSpots` | Integer | Общая вместимость слота |
| `availableSpots` | Integer | Свободные места на данный момент |
| `rentalAvailable` | Boolean | Доступен ли прокат на этом слоте |
| `rentalPrice` | Currency | Стоимость проката (если доступен) |

**Режим доступа приложения: R (Read-only)**
- Только чтение от бэкенда (ФТ-03)
- Горизонт показа — 7 дней по умолчанию (настраивается фильтром)
- Создание/редактирование слотов — в существующей инфраструктуре (админка)

---

### 5. Бронь

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | ID (сервер) | Уникальный идентификатор |
| `client` | Client.ID | Клиент, совершивший запись |
| `slot` | Slot.ID | Слот, на который записался |
| `status` | Enum: `активна`, `отменена клиентом`, `отменена мастерской` | Текущий статус |
| `rentalSelected` | Boolean | Выбран ли прокат инструментов |
| `createdAt` | DateTime | Дата и время создания |
| `cancellationReason` | String? | Причина отмены (только при отмене мастерской) |

**Режим доступа приложения: RW (Read-Write, без Delete)**
- **C** — запись на слот (ФТ-04)
- **R** — просмотр своих броней (ФТ-05)
- **U** — отмена (смена статуса) (ФТ-06)
- **D** — не предусмотрена: бронь не удаляется, только меняет статус

**Бизнес-правила:**
- Бесплатная отмена — за ≥4 ч до начала; <4 ч — только через поддержку (НФТ-05)
- При отмене мастерской указывается причина; повторная запись на этот слот запрещена (НФТ-06)
- Клиент записывает только себя (НФТ-07)
- Статус «отменена мастерской» выставляется со стороны бэкенда; приложение получает уведомление

---

### 6. Оценка мастера

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | ID (сервер) | Уникальный идентификатор |
| `client` | Client.ID | Клиент, поставивший оценку |
| `master` | Master.ID | Оцениваемый мастер |
| `slot` | Slot.ID | Слот, после которого поставлена оценка |
| `score` | Integer (1–5) | Оценка в звёздах |
| `createdAt` | DateTime | Дата и время оценки |

**Режим доступа приложения: WO (Write-only)**
- **C** — создание оценки (ФТ-07)
- **R** — агрегированный рейтинг читается через сущность Master (R-only)
- **U / D** — не предусмотрены

**Бизнес-правила:**
- Доступно через 1 ч после окончания слота, окно — 48 ч (НФТ-04)
- Клиент может оценить мастера только после посещённого занятия

## Сводная таблица

| Сущность | Read | Create | Update | Delete | Режим |
|---|---|---|---|---|---|
| **Клиент** | ✓ (свой профиль) | ✓ (регистрация) | ✗ | ✗ | **RW** |
| **Мастер** | ✓ | ✗ | ✗ | ✗ | **R** |
| **Программа** | ✓ | ✗ | ✗ | ✗ | **R** |
| **Слот** | ✓ | ✗ | ✗ | ✗ | **R** |
| **Бронь** | ✓ (свои) | ✓ (запись) | ✓ (отмена) | ✗ | **RW** |
| **Оценка** | ✗ (агрегировано в Мастере) | ✓ | ✗ | ✗ | **WO** |

**Легенда:**
- **R** (Read-only) — данные потребляются из бэкенда; приложение не управляет жизненным циклом
- **RW** (Read-Write) — приложение создаёт и/или изменяет сущность (полный или частичный CRUD)
- **WO** (Write-only) — приложение только создаёт; чтение — косвенное, через другую сущность
