# Use Cases

| ID | Название | Действующее лицо | Основной сценарий | Приоритет | Источник |
|---|---|---|---|---|---|
| UC-01 | Регистрация клиента | Клиент | Клиент вводит логин и пароль → система создаёт учётную запись → клиент получает доступ к приложению | Высокий | Сущность «Клиент», сценарий 1 |
| UC-02 | Вход в систему | Клиент | Клиент вводит логин и пароль → система аутентифицирует и открывает сессию | Высокий | Сущность «Клиент», сценарий 1 |
| UC-03 | Просмотр расписания | Клиент | Клиент открывает расписание → система показывает слоты на 7 дней с датой, временем, программой, мастером и свободными местами | Высокий | Сценарий 2, Сущность «Слот расписания» |
| UC-04 | Запись на слот | Клиент | Клиент выбирает свободный слот → при необходимости указывает прокат инструментов → система создаёт бронь со статусом «Активна» | Высокий | Сценарий 3, Сущности «Слот расписания», «Бронь» |
| UC-05 | Просмотр своих броней | Клиент | Клиент открывает раздел «Мои записи» → система показывает список броней с датой, временем, программой, мастером и статусом | Высокий | Сценарий 4, Сущность «Бронь» |
| UC-06 | Отмена брони клиентом | Клиент | Клиент выбирает активную бронь → система проверяет время до начала (≥ 4 ч → бесплатная отмена, < 4 ч → отказ с предложением обратиться в поддержку) → броня переводится в статус «Отменена клиентом» | Высокий | Сценарий 4, Бизнес-правила |
| UC-07 | Оценка мастера | Клиент | Клиент выбирает мастера после занятия → система проверяет окно оценки (1–48 ч после окончания) → клиент ставит 1–5 звёзд → рейтинг мастера обновляется | Средний | Сценарий 5, Сущность «Оценка», Бизнес-правила |
| UC-08 | Получение push-уведомления | Клиент | Система отправляет push-уведомление: (а) напоминание о предстоящем занятии или (б) уведомление об отмене занятия мастерской с причиной | Средний | Сценарий 6 |
